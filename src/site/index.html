Service Status

How it works

A scheduled GitHub Actions job checks every service about every 5 minutes. GitHub can delay scheduled runs, so gaps of 10 to 15 minutes are normal.

  • Vendor status pages (GitHub, Cloudflare, Google, Azure, Microsoft 365) are read from their official feeds. These are accurate but vendors often post late.
  • Direct probes load a real login page or API from GitHub's servers. These usually catch problems first. A probe only counts as failed if it fails twice, 15 seconds apart.
  • Alerts go to Teams and phone push only when something changes: a new problem, a worse problem, a new incident, or recovery.
  • Can't check means the status source itself could not be read 3 runs in a row. That's a monitor problem, not necessarily a vendor problem.
  • Not configured means the check needs credentials that haven't been added yet.

A direct probe failing from GitHub's servers doesn't always mean it's down for us. Check the vendor link before escalating.
